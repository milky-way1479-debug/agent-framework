# 本番接続前の条件

本ブランチの開発・保存依頼は、本番運用や規範の正式制定の承認ではありません。
以下は次の実装と本人の判断に必要な事項です。現状のコードにはproductionを有効にするスイッチはありません。

1. 憲法の論点A〜EとCONST-009〜011を本人が審議し、正式制定する。
2. その憲法に基づくAI法律を本人が審議・制定し、対象版を固定する。
3. 対象プロジェクト、目的、本人認証、承認UI、承認・停止・報告の経路を指定する。
4. 全Tool・LLM・通信先・データ分類・必要権限・資格情報を棚卸しする。
5. 提案役、実行役、承認経路、監査保存先をOS／サービスの権限で分離する。
6. 独立した実行ゲートを経由しない直接API、シェル、SDK、MCP、外部委任経路を拒否する。
7. 共同上限、費用・時間・再試行、結果不明時の照合、外部サービスの重複防止を実装する。
8. 子Agent、待機キュー、予約処理、外部委任の停止確認と安全な終了用枠を設計・検証する。
9. 監査記録の保持・削除・閲覧、独立保全、バックアップからの旧許可復活防止を実装する。
10. 第三者への影響、見直し経路、根拠提示と情報非開示の限界を定める。
11. 実サービスを含む代表ケースで試験し、未実装条件、残留影響、復旧不能範囲を本人へ提示する。
12. 本人が対象の版・構成・環境について本番有効化を明示決定する。

このチェックリスト自体は、新しい法律の制定や本人の決定を代替するものではありません。
