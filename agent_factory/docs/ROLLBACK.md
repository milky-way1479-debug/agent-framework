# ブランチと復旧

- 元の基準コミット：`f1fb145c4d80191aa86b3480d12112d828233763`
- 作業ブランチ：`feature/human-agent-governance-2026-10-04`
- `main` は変更せず、このブランチだけへ追加機能を保存する。
- Microsoftの `python/` と `dotnet/` の既存コードは変更しない。

## mainへ戻って元のフレームワークを確認する

未保存の作業がないことを `git status` で確認し、作業中の研究プロセスを終了してから切り替えます。

```sh
git switch main
```

ブランチの追加機能は残るため、再度確認する場合は次のように戻れます。

```sh
git switch feature/human-agent-governance-2026-10-04
```

## 将来、取り込み後に変更を取り消す場合

取り込んだ追加機能のコミットを確認し、`git revert <対象コミット>` で取消しの履歴を残します。
共有履歴を書き換える強制pushや、状態を破棄するresetを復旧の標準手順にはしません。

## コードと実行状態を分ける

コードを戻しても、使用済み承認、取消し、停止、実行済み／結果不明の操作、費用使用量を戻してはいけません。
実行状態のSQLite台帳と監査鍵はGitへ保存しません。コードのバックアップと一緒に古い台帳を復元しないでください。
不明な操作は結果不明のまま照合し、復旧を実行再開の承認と扱いません。

今回のdemoは一時ディレクトリ内の模擬操作のみで、終了後にその模擬台帳を破棄します。
本番での外部送信や既に発生した影響を、ブランチの切替で取り消せるという意味ではありません。
